HONEST LIMITS AND NEXT STEPS

What a production rollout needs next

Limits today

  • No authentication; MQTT without TLS
  • If broker and explorer are both down, a record is missed
  • Single node with the public default keys
  • conflicting and not_solid only seen in tests

Next steps

  • Backfill and reconcile from the Tangle
  • Auth on the explorer, TLS on the broker
  • Multi-node peering and real keys
  • Official Trust Manager schema with UPV

Demo data is illustrative: aeriOS publishes no official message schema, so it uses Trust Manager vocabulary.

We want to be clear about the limits. No authentication yet, and the broker runs without TLS: fine for a local demo, not for production. A record is only lost if the broker and the explorer are both down at once, and we have no backfill from the Tangle yet. It is a single node with the public default keys. The demo data follows the Trust Manager docs but is not an official schema.
