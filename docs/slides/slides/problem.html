THE PROBLEM

The Tangle proves, but it does not explain

Hex, not meaning

aeriOS trust data sits in the ledger as hex-encoded JSON behind 32-byte block ids.

No search

No lookup by tag, by date or by the component that sent a message.

No receipt

Nothing tells an operator a message is on the ledger, final, and unchanged.

“IOTA offers limited support to monitor the data stored in the Tangle and to verify the correct insertion of the messages.”

Source: Challenge 2 (O-CEI) brief, Context & Motivation

Eclipse aeriOS uses the IOTA Tangle so that trust information cannot be changed. That works. But for the people who rely on it, the Tangle is opaque: hex payloads, 32-byte ids, no search, and no easy way to know a message really landed and is final. The brief says this directly.
