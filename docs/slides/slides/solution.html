WHAT WE BUILT

Two applications and a parallel database

1 · EXTENDED aeriOS MESSAGES API

Same contract, now traceable

  • Unchanged POST /upload and HTTP 200
  • Forwards the block id and the exact bytes sent to Hornet
  • Optional type, source and trace metadata
  • Never fails an upload if the explorer is down

2 · ADVANCED EXPLORER

Searchable and verified

  • PostgreSQL record with readable metadata
  • REST search by block id, date and tag
  • Solidity via GET block metadata
  • Content check via GET block

The brief's four mandatory functions, one per line: integration, search, validation, content verification

Exactly what the brief asks for. First, the aeriOS Messages API, extended but backwards compatible: same endpoint, same HTTP 200, and after Hornet accepts a block it forwards the block id and the exact bytes it sent. Second, the Advanced Explorer: a PostgreSQL copy enriched with metadata, a search API, and verification of every block against Hornet.
